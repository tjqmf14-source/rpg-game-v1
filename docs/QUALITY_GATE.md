# Quality Gate

RELIC BOUND는 기능 추가보다 **실행 가능성과 회귀 방지**를 우선합니다.

## main 병합 필수 조건

모든 Pull Request는 다음 검증을 통과해야 합니다.

1. Godot 4.7.2 headless project import
2. Smoke test
3. Data integrity test
4. Gameplay regression test

하나라도 실패하면 main에 병합하지 않습니다.

## Data integrity

자동 검증 대상:

- JSON 루트 형식
- 빈 ID / 중복 ID
- 필수 이름
- 영웅·몬스터 기본 스탯
- 몬스터 드롭 아이템의 실제 존재 여부
- 아이템 타입
- stack limit
- 음수 장비 스탯

## Save safety

로드 시 다음 데이터를 신뢰하지 않고 정규화합니다.

- 존재하지 않는 영웅
- 중복 영웅
- 4인을 넘는 파티
- 존재하지 않는 아이템
- 음수 또는 stack limit 초과 수량
- 존재하지 않는 몬스터 도감 데이터
- 소유하지 않은 장비
- 잘못된 장비 타입
- 중복/3개 이상의 유물
- 비정상적으로 큰 월드 좌표
- 저장과 무관한 대화/메뉴 열림 상태

지원 버전보다 새로운 save 파일은 로드하지 않습니다.

## 개발 순서

새로운 대형 시스템을 계속 추가하지 않고 아래 순서로 첫 Vertical Slice를 완성합니다.

1. 안정화 및 자동검사
2. 실제 게임용 16px 에셋 규격 확립
3. 시작 마을 + 초원 맵
4. 실제 캐릭터/적 애니메이션
5. 전투 hitbox 및 스킬 구조
6. 첫 퀘스트
7. 첫 던전
8. 첫 보스
9. Windows export
10. 실플레이 검수 후 콘텐츠 확장

## 정의

CI PASS는 “프로젝트가 구조적으로 실행 가능하다”는 의미입니다.
재미, 밸런스, 연출, 장시간 플레이 안정성은 별도의 실플레이 검증 대상입니다.
